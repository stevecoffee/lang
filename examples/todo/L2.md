# L2 — architecture

Parent: L0, L1

One running app. No server. No account.

## Parts

1. **Screen** — full-screen text UI: draws the list, selection, edit mode, checkbox  
2. **Input** — turns key presses into actions (navigate, reorder, edit, toggle, add, delete, quit)  
3. **List state** — ordered todos in memory: selection index, which row is being edited  
4. **Store** — load on start, save when the list changes; local only  

## How they connect

```text
keys → Input → List state → Screen
                ↓
              Store (load at start, save on change)
```

## Runtime

- Single process  
- Full-screen text (terminal-style); exact toolkit chosen at compile  
- Store is one local place (file or equivalent); exact format chosen at compile  

## Boundaries

- Screen does not talk to disk; Store does  
- Input does not own the list; it asks List state to change  
- Nothing here is a web backend or sync service
